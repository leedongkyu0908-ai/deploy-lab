## 남은 한계
- **배포 검증 안 함(조건 5).** 커밋·푸시 → Render·Vercel 재배포 → 공개 API·휴대폰 확인과 그때의 커밋·시각 기록이 남았다.
- **커밋 전 상태에서 검증.** 커밋 후 같은 결과인지 다시 확인해야 커밋 동일성을 말할 수 있다.
- **목록 정렬 버그(003 이전부터 있던 문제).** 서버가 `SELECT id::text … ORDER BY id DESC`로 조회해, PostgreSQL이 문자열 열 `id`로 정렬한다. id가 10을 넘자 `9,8,…,3,17,16,…,10,1` 순서가 되어 새 메모가 목록 맨 위가 아니라 중간에 보인다. 저장 자체는 정상(201, DB 행 확인). 이번 스펙 범위 밖이라 고치지 않았다.
- **길이 기준은 JavaScript `length`(UTF-16 코드 단위).** 이모지는 1개가 2자로 셀 수 있다. 스펙대로 한글·영문으로만 경계를 확인했다.
- **기존 메모 보존.** 2자 규칙 이전에 저장된 1자 메모(id 10 `a`, 002 검증 때 추가)는 지우지 않았다.
- 검증 중 추가한 메모(id 12~17)는 실제 행으로 남아 있다.

로컬·배포 결과를 구분한다. 검증 스크립트는 메모를 실제 추가한다. 원래 데이터는 삭제하지 않는다.
